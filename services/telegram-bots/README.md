# Telegram-боты AGL и akaalexey

Подготовлен общий сервис для двух независимых ботов. Сейчас это код для будущего VPS: боты в Telegram ещё не зарегистрированы, токены не получены, реальные сообщения не отправлялись.

| Бот | Темы обращений |
| --- | --- |
| Личный | Работа и сотрудничество, идеи, обратная связь |
| AGL | Идеи для «Рублемёта», ошибки, отзывы |

## Как работает

1. Посетитель выбирает тему и присылает одно сообщение, фото или поддерживаемый документ.
2. Бот показывает получателя и просит подтвердить отправку. До подтверждения обращение Алексею не передаётся.
3. После отправки Алексей получает уведомление и копию сообщения в личном чате с соответствующим ботом.
4. Алексей использует функцию Telegram «Ответить» на уведомление или копию. Бот доставляет ответ тому же посетителю.

Повторное подтверждение не дублирует обращение. Если доставка не подтверждена из-за ошибки связи, автоматическая повторная отправка не выполняется. Неизвестному адресату ответ не направляется.

Кнопки ботов пока не добавлены на сайты: до регистрации нельзя указать действующие ссылки.

## Требования

- Linux с Python 3.11 или новее, SQLite в стандартной поставке Python.
- Для постоянной работы — systemd и исходящий HTTPS-доступ к api.telegram.org.
- Два отдельных токена из официального @BotFather.
- Приватный числовой Telegram ID получателя.

Внешних Python-пакетов и отдельного сетевого сервиса базы данных нет. Используется long polling; входящий HTTP-порт для ботов не требуется. Сайты размещаются отдельно.

## Проверка без подключения к Telegram

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile bot.py storage.py
```

15 тестов проходят. Тесты используют поддельный клиент Telegram и временную базу; запросов в Telegram нет. Тест отказа рабочего потока намеренно проверяет аварийный выход процесса.

Для проверки реального конфигурационного файла без сетевых запросов:

```sh
sudo python3 /opt/agl-bots/bot.py --env-file /etc/agl-bots.env --check
```

Результат содержит только названия ботов, режим и каталог данных. Значения токенов не печатаются.

## Что сделать после выбора VPS

1. В официальном Telegram @BotFather выполнить /newbot два раза. Рабочие названия: «Алексей · Обратная связь» и «AGL · Рублемёт». Доступность @имён проверяется при регистрации; имена ботов ещё не выбраны и не зарегистрированы.
2. Разместить этот каталог в /opt/agl-bots. Реальный файл настроек держать отдельно, в /etc/agl-bots.env с правами 600. Токены вводятся в этом файле на сервере, а не в репозитории или чате.
3. Вначале оставить OWNER_CHAT_ID=0. Это режим настройки: обращения не собираются и не направляются владельцу. Из своего Telegram открыть каждого бота и нажать Start. Команда /id возвращает ID отправителя только ему самому.
4. Указать свой положительный ID в OWNER_CHAT_ID и перезапустить сервис. Боты должны быть запущены владельцем в Telegram до приёма обращений.
5. Установить deploy/agl-bots.service в каталог unit-файлов systemd и включить его. Команды на реальном сервере будут уточнены под выбранную ОС.
6. Проверить настоящую отправку и ответ тестовым обращением после явного запуска владельцем.
7. Подтвердить сведения об обработке обращений, затем разместить ссылки на зарегистрированные боты на сайтах.

Сам сервис не удаляет ранее установленный webhook. Если он обнаружен, запуск останавливается с понятным сообщением: настройку нужно рассмотреть отдельно.

## Данные и ограничения

На сервере сохраняются числовые идентификаторы чатов и сообщений, тема, состояние отправки и сроки для маршрутизации. Текст, имена и вложения в SQLite не записываются; файлы не скачиваются на VPS. Сообщения остаются в Telegram по его правилам.

Черновик и выбор темы действуют 15 минут. Технические связи для ответов — до 30 дней; очистка выполняется работающим сервисом. /cancel удаляет локальный неотправленный черновик, но не удаляет ранее отправленные сообщения из чатов Telegram.

Принимаются текст, фото и документы PNG/JPG/WebP/PDF/TXT до 10 МБ. Одно обращение содержит одно последнее сообщение; альбомы не объединяются. Ограничение: пять обращений в час и не чаще одного в 15 секунд на человека и бота.

Ответы разрешены только настроенному владельцу. Обработка групп и каналов не включена. Веб-формы, оплаты, рассылки, аналитика, загрузка ссылок и регистрация пользователей не добавлены.

До публичного запуска нужно проверить поведение на настоящих ботах, права владельца, условия выбранного хостинга и соответствие уведомления о данных реальным процессам. Автоматические тесты не являются проверкой действующих токенов или юридическим заключением.
