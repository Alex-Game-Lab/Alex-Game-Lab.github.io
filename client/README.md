# Пространство AGL

Статический клиент для API AGL: новости, проекты, единый аккаунт и кабинет команды.
Обычный JavaScript + CSS, библиотека `oidc-client-ts` для OIDC/PKCE, esbuild только
на этапе сборки. Runtime сервера или npm на GitHub Pages не требуется.

```sh
cd client
npm ci
npm test
npm run build
cd ..
python3 tools/build_pages.py --sync-root
```

В `sites/agl/portal/assets` хранится проверяемый bundle. Существующий workflow
Pages собирает Python-экспорт с ним и не требует установки npm. Отдельный CI
проверяет, что bundle соответствует исходникам. Источники обоих публичных
сайтов сохраняются в `sites/agl` и `sites/akaalexey`; домен и workflow публикации
не менялись.

Публичные страницы: `/news/`, `/projects/`, `/account/`, `/workspace/`, `/portal/`.
Callback: `/auth/callback/`. Внутри клиента используются hash routes, поэтому
перезагрузка ссылки работает на GitHub Pages без серверных rewrite.
Статические страницы «Рублемёта» и портфолио продолжают работать без API.

Адреса API и issuer закреплены в `src/safety.js`. Их нельзя переопределить
параметром URL. CSP ограничивает подключение собственными API и AGL ID.
Токены находятся в памяти, PKCE state — в sessionStorage; localStorage
используется только для темы. Вход для операций управления требует отдельного
клиента `agl-console`, пароля и OTP. Скрытие кнопок в UI не заменяет проверку API.

Публикации и отчёты отображаются текстовыми DOM-узлами, не HTML.
Обложки выбираются из локального списка, произвольные внешние изображения
не загружаются. Нет платных QA-ролей, выдуманных новостей или участников команды.
При недоступном API показаны сообщение и повтор запроса, без имитации входа.
Публичная регистрация остаётся закрытой на стороне AGL ID до настройки SMTP.

Тестовый identity transport применяется только Node-тестами при сборке в памяти.
Он не входит в production bundle и не предоставляет тестового входа на сайте.
